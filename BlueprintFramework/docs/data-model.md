# 数据结构与变更通知

本文记录当前公共接口及其实现边界。BlueprintFramework 面向多个宿主项目；Core 只依赖 Qt Core，Quick 提供图编辑投影和画布，Demo 提供示例对象、节点实现和特殊界面。

## 数据归属

| 数据 | 所有者 | 内容 |
| --- | --- | --- |
| 类型定义 | 宿主项目作用域内的 `NodeRegistry` | 稳定类型 ID、端口、参数、属性和接口声明，以及显示信息。追加注册后定义不可变。 |
| 图配置 | `GraphDocument` | 图 ID、节点与连线、位置和参数覆盖值。 |
| 编辑状态 | `GraphEditSession` 与各视图 | 一份文档共享撤销历史；选择、悬停、视口和拖动预览由各视图持有。 |
| 运行状态 | 每个 `GraphRuntime` | 启动快照、本次执行身份、动作输出和当前异步调用。 |
| 业务对象 | 宿主项目 | 对象身份、配置、实时状态及外部请求。图中仅保存宿主可解析的引用。 |

图节点删除只删除图中的表示。宿主对象的生命周期和保存由宿主负责，同一对象可以被多张图或多个节点引用。节点配置更新通过文档提交，实时属性通知通过宿主通道传递，不用整图替换同步遥测。

`NodeRegistry`、`GraphDocument` 和 `GraphEditSession` 在编辑器所属线程使用。注册表必须比文档存活更久，文档必须比会话存活更久。节点定义指针在注册表存活期间有效；节点实例查询返回借用指针，文档编辑后需要重新查询。运行实例可以位于另一线程，跨线程前在文档线程创建值快照。

## 声明与图数据

```text
GraphData { id, nodes, connections }
NodeData { id, typeId, position, parameterOverrides }
ConnectionData { id, source, target }
Endpoint { nodeId, portKey }

SnapshotNode { id, typeId, parameters, ports }
GraphSnapshot { graphId, revision, nodes, connections }
```

节点和连线使用 `QUuid`。节点类型使用带模块前缀的稳定字符串，例如 `example.constant`。端口键、参数键、属性键和接口键分别在其声明范围内唯一，显示文案与键分开。连线始终保留完整的 `{nodeId, portKey}`，不以模型行号、显示名称或 QML 对象定位。

| 声明 | 主要字段与规则 |
| --- | --- |
| `NodeTypeDefinition` | 类型 ID、名称、描述、符号、分组、参数、端口、属性、接口和实例数量规则。 |
| `PortDefinition` | 稳定键、方向、显示名、`PortKind`、值类型和可选输入默认值。执行端口不声明值类型，也没有默认值。 |
| `ParameterDefinition` | 稳定键、值类型、默认值、字符串候选值、显示名、说明、数值上下界与整数约束。 |
| `PropertyDefinition` | 用 `ParameterDefinition value` 复用值声明，另声明 `writable`。值归宿主或运行实例。 |
| `MethodDefinition` | 稳定键、显示名，以及按值声明组织的输入、输出。具体调用由宿主实现。 |

属性的 `writable` 默认为 `false`，表示允许读取但禁止设置。Quick 的类型元数据保留该标记；设置属性只提供可写成员，没有有效可写目标时禁用输入与应用。宿主的实际写入入口必须再次检查权限，拒绝只读写入且保持状态不变。节点自身的配置参数仍由文档编辑，与对象属性写权限分开。

当前值类型为 `bool`、`number` 和 `string`。`number` 接受有限的 `int`、`uint`、`float` 和 `double`，不把字符串或布尔隐式转换为数值；`integer` 表示数值必须是数学整数，不是独立的 64 位整数类型。当前没有自定义值类型或无损大整数编码。 数据输入可声明 `anyValueType`，接受这三种具体值类型；它不用于参数、属性或输出，不接受执行信号，也不引入隐式类型转换。通用比较节点使用两个独立的 `any` 输入，并按实际类型决定运算结果。

字符串的 `allowedValues` 保存稳定值。数值的 `minimum`、`maximum` 为闭区间，缺少边界表示不限制。注册默认值、编辑、加载和宿主成员数据通过 `NodeRegistry` 的同一套类型及约束校验。宿主读写成员和处理接口输入输出时使用其正式声明，避免在界面和执行端分别维护范围。

`NodeData.parameterOverrides` 只保存配置覆盖值。缺少覆盖时读取定义默认值；没有默认值且没有覆盖表示未设置。调用 `setParameters` 时用无效 `QVariant` 清除覆盖，恢复默认或未设置状态。无效值不作为持久化参数值保存。

数据输入端口没有连线时使用 `defaultValue`；没有默认值则在求值时报错。默认值随声明或 `resolvePorts(const NodeData &)` 解析，不另存一份端口值。例如设置属性节点可由已校验的 `value` 参数派生输入默认值。

固定端口直接使用 `ports`。`resolvePorts` 可根据当前节点配置及稳定的成员声明返回完整的实例端口列表；不能依赖其他节点的可变配置或实时宿主状态。读取属性节点保存目标和成员引用，输出类型从成员声明解析，不保存 `memberType` 镜像。未绑定端口可暂时使用空值类型，此时不可连线或求值。

`NodeRegistry::add` 追加不可变定义，拒绝重复类型 ID 或无效声明。`definitions()` 按注册顺序返回声明快照。`typeAdded` 经文档投影为 `typesChanged`，让已打开的会话刷新节点库；类型追加不改变文档 revision、保存点或撤销历史。不提供定义替换、热卸载或兼容类型别名。

## 数据与图的对应关系

一份文档管理一份图，可投影到多个画布。不同画布看到相同的节点、参数和连线，各自持有视口与选择。节点位置使用画布坐标，视口平移缩放只改变显示位置；连线几何由端口当前布局派生。

| 关联 | 定位方式 | 对应关系 |
| --- | --- | --- |
| 节点实例 → 类型 | `typeId` | 多个实例共享一个不可变类型定义。 |
| 连线 → 端口 | 图内的 `nodeId + portKey` | 先定位节点，再查询已解析端口。 |
| 文档 → QML | 节点或连线 ID | 模型行号只用于投影，编辑和选择使用稳定 ID。 |
| 节点 → 宿主对象 | 扩展定义的对象引用 | 宿主负责解释命名空间、查找和对象失效。 |
| 文档 → 运行实例 | `graphId + revision` 的启动快照 | 同一图可以同时创建多个独立实例。 |
| 一次动作 → 完成回调 | `runtimeId + executionId + callId` | 停止、重启或重复完成都不能误推进其他调用。 |

例如同一设备可以在配置卡片和操作节点中使用不同节点 ID，却引用相同的宿主对象。移动卡片、修改图内展示选择或绑定走文档；设备地址、实时播放状态和真实设备请求走宿主。对象失效时由宿主给出可定位诊断，不将对象指针写入图文件。

## 文档写入和变更边界

`GraphDocument` 是图配置的统一写入口。`canConnect` 无副作用，提交连线时再次检查端点、方向、类别、值类型、重复连线和输入占用。每个输入最多一个来源；数据输出可连接多个目标，执行输出最多一个目标。执行端口只传递触发信号。

节点类型可声明实例规则：

| 规则 | 行为 |
| --- | --- |
| `Multiple` | 同类型可以创建多个实例。 |
| `SinglePerDocument` | 每张图最多一个此类型实例。 |
| `UniqueByParameter` | 同类型按指定字符串参数的有效非空值去重。 |

创建、参数修改和整图替换都执行实例约束。冲突时 `EditResult.conflictingNodeId` 指向已有节点；Quick 的 `placeNode` 返回该 ID，供画布定位。

`reconnectConnection(connectionId, source, target)` 原子修改已有连线的端点并保留连线 ID，校验时只排除该连线自身的占用。成功后同一 ID 同时列入 `removedConnectionIds` 与 `addedConnectionIds`，投影读取提交后的端点；重连失败或端点未变时不产生通知和撤销记录。

一次编辑先构造并校验候选数据，再提交，最后发出一次 `changed(changeSet)`。失败或没有实际变化时不递增 revision；删除节点和关联连线属于同一次提交。通知回调中直接修改文档会被拒绝，调用方应在通知结束后提交。

```text
GraphChangeSet
  revision / reset
  addedNodeIds / removedNodeIds
  changedNodes [{ nodeId, positionChanged, parameterKeys, portsChanged }]
  addedConnectionIds / removedConnectionIds
```

`parameterKeys` 只列实际变化的配置键；派生端口改变时设置 `portsChanged`。参数及其派生端口一次原子更新，已连线端口必须保持存在、方向、类别和类型兼容；不兼容时整次修改失败，调用方先显式断线。当前不提供自动删线或重连回退。

`setParameters` 可一次更新多个相关参数，Quick 直接暴露该操作，并提供 `resetParameter` 清除单项覆盖。一次批量修改对应一个撤销步骤。撤销、重做恢复相同节点和连线 ID，并产生新的 revision；保存后的干净状态由共享编辑历史的保存点跟踪。

| 操作 | 文档通知 | 编辑器响应 |
| --- | --- | --- |
| 改参数及派生端口 | 节点、实际变更键和端口标记 | 更新节点和属性面板，重算相连线锚点。 |
| 提交移动 | 一个节点 ID，位置变化 | 更新位置及相连线几何。 |
| 增删连线 | 连线 ID | 刷新连线投影。 |
| 删除节点 | 节点与关联连线同批移除 | 先删除连线，再删除节点。 |
| 撤销删除 | 原节点与连线同批加入 | 先插入节点，再插入连线。 |
| 整图替换 | `reset` | 重建投影及编辑历史，清理失效选择。 |

## 从文档通知到 QML

`GraphEditSession` 提供节点 `QAbstractListModel`、只读连线列表、编辑入口、撤销历史、错误消息和结构化诊断。同一文档的多个视图绑定同一会话。外部整图替换会重建历史，因此不用于实时状态刷新。

节点模型投影 ID、类型、名称、位置、当前参数和已解析的输入输出端口。每个端口包含稳定键、显示名、值类型及执行类别。`nodeTypes` 提供类型显示信息和参数声明；追加类型时单独通知。参数编辑和端口变化通过 `dataChanged` 报告实际角色，节点增删使用对应模型行通知。

`GraphEditor` 默认根据元数据生成节点库和属性面板。布尔使用复选框，字符串候选使用下拉框，其余参数使用文本或数值输入，并可恢复默认。Core 始终负责最终校验。宿主可注入 `palettePanel`、`inspectorPanel` 和 `nodeContents`，特殊对象选择器与成员操作仍由宿主实现。

自定义节点内容根项声明 `property var node`，读取 `id`、`typeId`、`title` 和 `parameters`，以 `implicitHeight` 提供高度。节点外壳处理标题拖动和端口布局；端口锚点先使用节点局部坐标，再映射到画布视口。拖线命中以视口像素计算，`ConnectionLayer` 接收已映射的线段端点。

端口支持双向拖线与依次点击。拖动已连接输入时，以原连线的来源输出作为固定端，放到另一输入后更换目标，并保留所拖连线的 ID 及其它分支；输出拖到已占用输入时重接该输入的连线；已连接执行输出拖到新输入时更换目标；数据输出向空闲输入添加分支。重连预览只隐藏正在重接的原线，文档在有效放置后一次提交；取消或无效放置保留原线。`connectionProposal` 由吸附预检和提交共用，统一端点方向及替换连线 ID，保证显示的合法性与实际提交一致；`completeConnection` 继续由点击和拖拽释放共用。

`GraphEditor.interactionCanceled()` 统一取消拖放、拖线、节点移动和平移；窗口失活、Esc、模型重置或切换图时结束预览，节点移动和平移恢复原位置。画布仅在自身获得焦点时处理 Delete 与撤销重做，文本控件保留自己的编辑行为。Demo 通过 `NodeDragSource` 共用节点库及成员的拖放预览和取消流程。

拖动期间只更新视图预览，释放时提交一次位置修改。视图按稳定 ID 保留仍存在的选择。宿主属性更新独立刷新卡片和预览，不写入图配置、不产生图撤销记录。节点规模和帧时间需要在目标机器上实测后再决定实例化或连线绘制优化。

## 运行契约

`GraphDocument::snapshot()` 在文档线程解析参数默认值和实例端口，返回不包含画布坐标的逻辑值快照。`GraphRuntime::start(snapshot, implementations)` 校验快照结构、端口和连接，并分别拒绝数据依赖环与执行流环。启动后文档编辑不影响此实例，修改在下次启动生效。

运行实例的方法在其所属线程调用。计算和动作入口也在该线程执行；宿主负责把跨线程对象访问排队到对象所属线程。`Q_INVOKABLE` 不改变普通 C++ 调用的线程归属。回调捕获的宿主服务必须在运行实例停止前保持有效；运行实例不拥有宿主对象。

`RuntimeImplementations` 按类型 ID 提供三种回调：

| 回调 | 输入与结果 |
| --- | --- |
| `evaluators` | 接收启动参数和按数据输入端口键组织的值，返回 `EvaluationResult{outputs, error}`。 |
| `actions` | 接收 `ExecutionContext` 和完成回调，完成时提供 `ActionResult{exitPort, outputs, error}`。 |
| `cancellations` | 按当前 `callId` 请求取消宿主异步操作，可省略不支持取消的实现。 |

同一类型选择计算输出或动作输出，不同时注册两种实现。对象成员声明供宿主校验；Core 不自动反射或调用 `QObject` 成员，也不维护第二份宿主属性值。

`evaluate(endpoint)` 接受数据输入或数据输出。输入沿连线读取上游，无连接时使用端口默认值；输出按完整端点解析。一次需求值内共享上游结果，菱形依赖只计算一次；下次求值重新调用纯计算，能够读取宿主最新状态。输出必须包含全部声明的数据输出，不能包含未知键，且逐项符合已解析值类型。

`execute(executionOutput)` 从执行输出触发，返回本次 `executionId`。一个实例同时只受理一次执行，忙时显式返回诊断；不同实例可交错等待。执行总是排队启动，完成信号不会早于受理返回。执行输入和执行输出都最多一条连线；动作选择出口后沿该出口继续，每次只发起一个动作，完成后才继续。

`ExecutionContext` 含 `runtimeId`、`executionId`、`callId`、`nodeId`、启动参数、数据输入和触发的执行端口。异步动作如需保留上下文，应复制所需字段。同步动作也调用同一个完成回调，框架统一排队处理结果。

成功动作返回已声明的执行输出键，或留空结束此分支。非空诊断结束整次执行；结果输出与纯计算共用校验。动作输出仅在该动作于本次执行完成后可读，下次执行前全部清空。数据依赖不会隐式触发尚未执行的动作。

`stop()` 先使运行身份与当前调用失效、清除执行位置及结果，再请求宿主取消；活动执行收到 `runtime.cancelled` 完成诊断。完成回调可以从任意线程调用，结果排队回运行线程后再次核对三层身份，重复或迟到结果被忽略。运行对象销毁后仍可安全调用之前保存的完成回调。取消只代表请求，已发送的外部命令由宿主按实际能力处理。

`executionFinished(executionId, Diagnostic)` 报告受理后执行的成功、失败或取消。实时属性变化属于宿主通知，与某次接口调用完成分别处理。预览和正式执行使用不同实例，避免预览替换执行快照或共享动作结果。

### 运行实现中的独立函数

以下六个私有函数都有当前实现中的实际共享逻辑或独立回调边界：

| 函数 | 独立用途 |
| --- | --- |
| `evaluateValue` | 公开端点求值、纯节点输入和动作输入都需要端点解析、默认值及上游取值，三条路径共用规则。 |
| `evaluateNode` | 递归计算上游并共享缓存；多个端口指向同一节点时复用完整输出。 |
| `validateOutputs` | 纯计算返回与异步动作返回都必须执行相同的完整输出及类型检查。 |
| `advance` | 既是排队执行的启动入口，也是动作完成后的继续入口，保证一次只发起一个动作。 |
| `complete` | 异步结果投回运行线程后的独立处理入口，核对身份、校验结果并推进。 |
| `finish` | 空执行、求值失败、动作失败和成功都需要统一清理本次执行并通知。 |

其他新增的共享函数也有实际调用依据：

| 函数 | 独立用途 |
| --- | --- |
| `connectionProposal` | 吸附预检和提交共用端点及替换连线的解析，防止两处占用判断产生不同结果。 |
| `validateParameterDefinitions` | 注册节点参数、属性、方法输入和方法输出时共用键、类型、默认值及约束校验，避免四份声明规则。 |
| `DemoGraph::runtimeImplementations` | 正式运行和独立预览都需要注册完整的示例求值、动作与取消实现，两处共用同一组业务实现。 |

`nodeTypes`、`diagnostic`、`objectMembers` 等查询以及批量编辑、重置参数是 C++/QML 的公开属性或调用入口；其独立签名由 Qt 属性和元对象调用要求决定。

`CompletionGate` 只保护异步投递与 `GraphRuntime` 析构之间的对象指针访问。完成回调持有门闩，不持有运行对象；投递时加锁，析构先在同一锁下清除指针。运行对象存活时排队到其线程，销毁后直接忽略结果，避免跨线程检查对象存活与投递之间的竞态。

## 诊断与持久化

公共 `Diagnostic{code, message, nodeId, key}` 的空 `code` 表示成功。调用方根据稳定代码判断错误，消息负责展示；节点和成员或端口键提供定位，不通过解析消息决定行为。Quick 同时提供 `error` 字符串和 `diagnostic` 对象。

JSON 使用当前 `version: 1` 格式，只保存图 ID、节点 ID、类型、位置、参数覆盖值和连线端点。类型声明、运行输出、宿主对象指针和实时状态都不保存。加载先解析临时图并完整校验，成功后一次替换；未知类型、无效值或不支持的格式版本保留当前文档。保存使用原子写入。

现阶段直接同步更新公共模型、Demo 与现行格式，不提供旧接口适配、节点类型别名、版本迁移或缺失扩展占位。

## 验证与当前边界

文档测试覆盖共享动态注册、参数约束、清除覆盖、原子批量修改、派生端口和撤销投影。运行测试覆盖多输出、共享依赖、实时宿主读取、快照、默认输入、输出校验、无环约束、异步失败、跨线程及重复完成、停止后迟到结果、实例隔离和销毁后回调。比较测试覆盖数值、字符串、布尔和异类输入的 348 条矩阵，以及参数、保存读取、撤销和已放置对象投影。交互测试使用真实鼠标键盘，覆盖阈值、取消、平移、文本焦点、吸附反馈和重连一致性。命令见 [README](../README.md#构建和验证)。

当前已实现追加式注册、配置派生端口、基本类型及成员声明、原子文档编辑、默认编辑界面和无环顺序执行。二进制扩展加载与卸载、自定义值类型、循环、并行动作、外部事件队列、通用变量节点、子图和执行调试面板均未实现；这些能力按明确用例单独设计，不以占位接口加入当前公共模型。
