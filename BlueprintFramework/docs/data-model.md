# 数据结构与变更通知

当前 C++ 核心提供基础值类型、节点类型注册、图文档编辑、提交后通知与 JSON 读写。`BlueprintFramework-demo` 用 QML 画布验证编辑闭环。本文记录现有契约与后续接入设计。

## 数据归属

| 数据 | 所有者 | 内容 |
| --- | --- | --- |
| 类型定义 | 宿主或内置节点注册表 | 类型 ID、端口定义、参数类型和默认值。打开文档后，已使用的定义保持稳定。 |
| 图数据 | `GraphDocument` | 图 ID、节点、连线、位置和持久化的参数覆盖值。文档对外提供查询和受校验的编辑入口。 |
| 编辑状态 | 文档与各视图 | 同一文档的编辑视图共享撤销历史。选中项、悬停、视口和拖动预览由各视图持有。 |
| 运行状态 | 每个运行实例 | 启动时的逻辑快照、实例变量、事件队列，以及单次执行的结果和等待状态。 |
| 业务对象 | 宿主项目 | 设备、素材等对象及其配置。图节点保存可解析的引用，宿主负责查找、更新和生命周期。 |

`GraphData`、`NodeData` 和 `ConnectionData` 是普通 C++ 值类型。注册表和文档共享节点类型定义。QML 通过模型角色读取节点，宿主无需为每个节点创建一个 `QObject`。节点 ID 与连线 ID 使用 `QUuid`，节点类型使用带项目或模块前缀的字符串，例如 `example.constant`。显示名称和排列顺序可以独立变化。

```text
GraphData { id, nodes, connections }
NodeData { id, typeId, position, parameterOverrides }
ConnectionData { id, source, target }
Endpoint { nodeId, portKey }
```

参数键表示节点自己的配置。数据输入未连线时，可以使用端口的默认值或节点实例的覆盖值。两类值分别保存。覆盖项不存在时回退到类型定义的默认值，清除覆盖项表示恢复默认。`QVariant` 承载值，`valueTypeId` 决定校验、解析和持久化规则。第一版限定布尔、数值和字符串。字符串参数可通过 `allowedValues` 限定候选值，注册默认值、编辑和加载共用校验。选项的显示标签由界面提供，图文件保存所选的字符串值。整数与对象引用在对应节点进入实现时定义其精确值域和编码。图文件保存可解析的值和标识，设备指针与 QML 对象留在各自拥有者内。

## 数据与图的对应关系

一份 `GraphDocument` 管理一份 `GraphData`，可以投影到多个画布。不同画布看到相同的节点、参数和连线，各自保留视口与选择。对画布外的节点，文档记录依然存在，编辑器可以按需创建节点组件。

| 关联 | 定位方式 | 对应关系 |
| --- | --- | --- |
| 节点实例 → 类型定义 | `NodeData.typeId` → `NodeTypeDefinition.typeId` | 多个实例可共用一个类型定义。编辑器按类型确定端口、参数和默认外观。 |
| 连线端点 → 节点端口 | 图内的 `nodeId + portKey` | 先找到节点，再从其类型定义或实例端口中查找端口。连线引用稳定键，画布根据当前布局计算锚点。 |
| 图数据 → QML | 当前文档中的节点 ID 或连线 ID | 模型把数据投影为行。行号、QML 对象和屏幕位置随视图变化，选择与编辑以 ID 为准。 |
| 节点 → 宿主业务对象 | 参数中由扩展定义的对象引用，宿主解析 | 一个引用指向一个业务对象。同一对象可以被同一张图或多张图中的多个节点引用。 |
| 图数据 → 运行实例 | 图 ID、启动时的文档版本和运行实例 ID | 一份图可启动多个实例。状态按运行实例 ID 和节点 ID 投影到画布，执行结果留在运行时。 |

`graphId` 表示文档身份，跨图定位节点时使用 `graphId + nodeId`。连线的两个端点属于当前图。节点的位置以画布坐标保存，视口缩放和平移只改变它的屏幕位置。连线的控制点可以按布局派生，首版只持久化端点。

属性面板根据选中节点的 ID 查找实例，再把类型定义中的默认值与实例覆盖值合成当前显示值。对于图自己持有的参数，例如常量节点的 `value`，节点内控件和属性面板都向 `GraphDocument` 提交修改。文档发布该节点及参数键的变更，两处从同一份数据更新。

对于宿主已有的设备，例如 `projector-001`，配置图中的设备卡片和流程图中的设备引用节点可以分别使用不同的 `nodeId`，同时引用同一台设备。图中各自保存节点位置、设备引用和需要持久化的展示选择。地址由宿主保存，编辑时走宿主的校验和更新入口，再由设备属性通知刷新相关视图。移动卡片、修改展示字段或重新绑定设备走图文档的通知。设备被删除时，关联节点可显示引用失效并继续保留原引用，方便重绑。

命令行示例用 `常量.value → 显示.input` 验证图内的参数和连线。接入 QML 后，用节点修改通知验证只更新受影响的模型行，再用零端口的资源节点验证外部数据关联。两张图引用同一个示例资源，修改资源属性后两张图的卡片同步，移动其中一张图里的卡片只更新该图的布局。

## 扩展节点、端口与属性

1. **节点定义**。宿主通过 `NodeRegistry::add` 注册 `NodeTypeDefinition`。同一 `typeId` 唯一，参数键和端口键在各自类别中唯一。文档创建时复制注册表。当前支持 `bool`、`number` 和 `string`，其中 `number` 接受有限的 `int`、`uint`、`float` 和 `double` 值。静态配置节点可以只有参数，也可以由宿主提供完整的自定义编辑器。
2. **编辑器扩展**。默认属性面板根据参数定义选择控件。按 `typeId` 注册的 QML 节点组件或编辑器可提供特殊显示，通过统一的编辑入口提交图参数。设备等宿主资源属性提交到宿主的修改入口。
3. **运行扩展**。运行时按 `typeId` 查询求值或动作实现。执行端口和数据端口在运行阶段显式区分，执行端口只用于选择后续节点。声明、表现和执行分开注册，以相同类型 ID 关联。
4. **动态端口**。固定端口直接使用定义键。需要动态端口的节点保存各实例稳定的端口键和顺序。修改参数导致端口变化时，先计算新端口和受影响连线，再在同一次操作中应用。已有端口调整位置时保留键。删除已连线端口时，由编辑动作明确拒绝或同时删除受影响连线。

静态数据输入端口可以使用 `anyValueType`（`any`），接收 `bool`、`number` 或 `string` 输出，各输入独立匹配，不要求同一节点的输入类型一致。它只表示输入端口的连接范围，实际值保留具体类型；执行信号不能连接到该输入。输出端口、参数和动态端口类型候选继续使用具体类型，普通端口仍要求类型相同。

Demo 的 `demo.compare` 使用两个 `any` 输入和一个 `bool` 输出。字符串参数 `operator` 默认 `eq`，候选值为 `gt`、`ge`、`lt`、`le`、`eq`、`ne`，图文件保存该稳定值。数值按数值类型比较，字符串和布尔值按原值支持等于、不等于；异类值以及尚未支持的同类关系运算返回 false，异类的不等于也返回 false。未连接或未求值的输入仍使节点保持未求值。

## 文档写入和变更边界

节点类型可以声明 `instancePolicy`。`Multiple` 为默认策略。`SinglePerDocument` 限制同一类型每张图最多一个实例。`UniqueByParameter` 按类型与 `instanceKeyParameter` 指定的字符串参数值去重，使用覆盖值或类型默认值，要求有效值非空。实例约束适用于创建、更新参数和整图替换。整图替换发现冲突时保留当前文档。

`GraphDocument::addNode` 遇到实例冲突时返回错误和 `conflictingNodeId`。`GraphEditSession::placeNode` 在此情况下返回已有节点的 ID，供画布选中定位。实例规则随类型注册表提供，图文件保存节点绑定参数。宿主按绑定值解析对象并提供状态通知。

`GraphDocument` 是图数据的写入入口。最先实现 `addNode`、`moveNode`、`setParameter`、`connectPorts`、`removeConnection` 和 `removeNode`。`canConnect` 提供无副作用的预检，正式提交重新检查方向、类型、重复连线和端口连接数量。

一次成功编辑按以下顺序发生：

1. 校验输入与受影响的图结构，计算实际变化。接入撤销后，文档的编辑历史保存撤销所需的旧值。
2. 提交节点和连线，递增文档 `revision`。不变更任何值的操作和校验失败的操作保持原 revision。
3. 发布一次提交后的 `changed(changeSet)`。观察者查询到的是已经一致的文档。通知回调中发起的编辑会被拒绝，调用方可在通知结束后再次提交。

```text
GraphChangeSet
  revision
  reset
  addedNodeIds / removedNodeIds
  changedNodes [{ nodeId, positionChanged, parameterKeys }]
  addedConnectionIds / removedConnectionIds
```

`parameterKeys` 记录实际变化的键。删除节点及其关联连线是一次提交。后续支持动态端口时，端口结构变化使用独立标记。画布接入后，连续拖动期间只更新预览位置，释放时提交一次 `moveNode`。撤销时恢复同一组 ID。一个成功的撤销或重做也产生新的 revision。保存后的干净状态由编辑历史的保存点跟踪。

| 操作 | 文档通知 | 编辑器响应 |
| --- | --- | --- |
| 改一个节点的参数 | 一个节点 ID 和实际变更的键 | 更新该节点和正在显示它的属性面板 |
| 提交移动 | 一个节点 ID，位置变化 | 更新位置，重算相连边的锚点 |
| 新增或断开连线 | 连线 ID 增删 | 在连线模型插入或移除行 |
| 删除节点 | 节点和关联连线 ID 同批移除 | 先移除连线行，再移除节点行 |
| 撤销删除 | 原节点和原连线 ID 同批加入 | 先插入节点行，再插入连线行 |
| 切换到另一份文档 | 编辑器切换数据源 | 重新绑定投影、清理选择，使用目标文档的编辑历史 |

## 从文档通知到 QML

`BlueprintQuick` 的 `GraphEditSession` 为一份文档提供节点模型、只读连线列表、编辑入口和撤销历史。同一文档的多个视图绑定同一会话。会话借用文档，宿主保证文档在会话销毁后再销毁。节点投影持有行顺序、ID 和用于显示的数据，所有修改提交到文档。文档提交后，投影先用旧行缓存调用 `beginInsertRows` 或 `beginRemoveRows`，然后更新自己的行数据并调用对应的 `end` 方法。改值走 `dataChanged`，只报实际变化的行和角色。整图替换通过 `reset` 通知重建投影。外部替换文档会重建历史，撤销和重做通过同一会话恢复快照。

宿主通过 `GraphEditor` 嵌入画布，可传入 `palettePanel`、`inspectorPanel` 和按 `typeId` 索引的 `nodeContents`。自定义内容根项声明 `property var node`，读取 `id`、`typeId`、`title` 和 `parameters`，并以 `implicitHeight` 提供高度。节点外壳管理标题拖动和端口布局。端口使用节点局部坐标，位置或端口布局改变时由画布重新映射，内部 `ConnectionLayer` 只接收视口坐标的线段端点。拖线命中按视口像素计算。

平移缩放、按 ID 保存的选择和拖动预览属于各个视图。拖动只更新预览，释放时提交一次位置修改。撤销和重做恢复原节点和连线 ID，当前选中节点仍存在时保留选择。Demo 提供节点类型、计算预览、控件和文件对话框。后续按实际节点规模测量对象数和帧时间，再决定节点实例化与连线渲染的优化方式。

文档、模型和 QML 在编辑器所属线程使用。运行实例使用逻辑快照，异步结果回到运行实例的线程后验证调用标识，再发布状态。状态通知带图 ID、运行实例 ID 和节点 ID，必要时带执行 ID。编辑器按当前选择的运行实例显示状态，宿主属性更新也按对象 ID 和属性键路由。

## 编辑交互约定

`GraphEditor.interactionCanceled()` 取消当前视图中的交互。开始放置节点、拖动标题、开始新的连线或中键平移时，先取消旧手势。Esc、切换会话或图 ID、整图模型重置、窗口失活也会取消；已取消的拖动在鼠标释放后不提交。取消标题移动和平移会恢复原来的位置，不增加文档 revision 或撤销记录。

画布空白处左键选择或清除选择，中键拖动平移，滚轮以光标位置缩放。标题拖动超过屏幕拖拽阈值后，从当前位置起算位移；本次手势只判定一次阈值，回到位移原点后继续跟随，不重新进入死区；拖动期间保持抓取手形。画布自身获得焦点时处理 Delete 和平台标准撤销、重做快捷键。节点内容中的文本输入控件先处理自己的按键，不把未处理的删除和撤销升级为图编辑；弹窗继续使用 Qt 控件自身的按键处理。

`NodeDragSource` 是节点库和对象成员共用的拖放入口。宿主设置 `graphEditor`、`title` 和可选的 `dropText`，在 `dropped(position)` 中创建对应节点。组件只提供预览、取消和落点，不创建业务对象。释放时先结束手势并将焦点归还活动窗口的画布，再通知宿主，宿主弹出的菜单可正常取得焦点；窗口失活取消不抢走文本输入焦点。预览表示节点标题区域，左上角就是最终节点的落点；标题区域按画布缩放，提示文字使用屏幕字号。落点以图坐标传给宿主，只检查指针是否处于画布空白处，不要求新节点的完整区域与其他节点无重叠。节点创建和绑定参数应在一次提交中完成。

`GraphEditSession::canConnect` 返回空字符串表示允许，否则返回原因，不改变文档、历史或会话的 `error`。画布在端口周围 16 个屏幕像素内优先选择最近的合法目标，并将预览吸附到其锚点；没有合法目标时，最近的非法目标显示错误反馈。提交仍由 `connectPorts` 再次校验。当前对已占用的输入拒绝连接，不自动替换；拖线释放后结束连线手势，点选输入失败则保留待连接状态，允许重试或按 Esc 取消。

## 持久化和落地顺序

图文件使用版本化 JSON，保存图 ID、节点、参数覆盖值、持久化布局和连线端点。加载到临时文档后统一校验，成功后替换当前文档。未知节点类型会导致加载失败并保留当前图。需要打开缺少可选扩展的项目时，再实现保留原始字段和连线的占位节点。

| 次序 | 交付与验证 |
| --- | --- |
| 1 | 基础值类型和独立 CMake 工程。命令行示例构造两个通用节点，以稳定端点键连接。 |
| 2 | 已实现注册表、文档写入和提交后通知。示例验证非法连接不通知、删除节点和关联连线只通知一批。 |
| 3 | QML Demo 支持添加、移动、拖线、参数编辑、撤销和保存恢复。后续用零端口资源节点验证宿主对象静态编辑。 |
| 4 | 宿主接入和运行时。用设备引用验证现有数据不重复保存，用两份运行实例验证事件隔离与停止后的回调处理。 |
