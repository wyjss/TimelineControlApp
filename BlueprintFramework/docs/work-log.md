## 2026-11-12

本轮范围为 BlueprintFramework 的编辑交互、Demo 通用比较节点及所需的核心输入端口校验。框架面向多个宿主项目提供图形化编程能力，业务示例继续由 Demo 提供。当前操作说明见[README](../README.md)，接口与数据契约见[数据结构与变更通知](data-model.md)。

### 完成内容

- 节点库分类支持收起、展开；节点改为拖放创建，单击条目不创建。节点库与对象成员共用 `NodeDragSource`，提供随画布缩放、与落点对齐的标题预览及可放置状态提示。
- 已有宿主对象以引用节点放置，节点库显示「已放置」；重复拖入定位已有卡片，删除、撤销、重做和绑定变化同步更新状态。
- 调试阶段关闭窗口直接退出；打开另一张图时仍保留丢弃未保存修改的确认。
- `GraphEditor.interactionCanceled()` 统一结束交互。Esc、窗口失活、切换图或会话、模型重置可取消手势；取消节点移动或画布平移恢复原位置。画布快捷键与文本控件自身的删除、撤销行为按焦点区分。
- `GraphEditSession::canConnect` 提供无副作用预检。拖线在 16 个屏幕像素范围内优先吸附合法输入；非法目标显示原因，正式连接再次校验。已占用的输入继续拒绝新连线。
- 节点标题拖动只判定一次启动阈值，从越过阈值的位置起算，修复起步跳跃及回到原点后重新进入死区的问题。拖动期间通过不接收鼠标按下事件的区域固定抓取光标，结束后恢复。
- 连线 Canvas 使用 `FramebufferObject` 与 `Cooperative`，保留原绘线和命中逻辑；软件后端已验证可由 Qt 回退为 Image 并正常绘制。
- 节点库统一提供 `demo.compare`，节点内选择六种运算符。A、B 使用独立的 `any` 数据输入，输出为布尔值。数值支持全部六种运算；同类型字符串、布尔值支持等于与不等于，其余暂返回 false。异类值全部返回 false，包括 `!=`；缺输入或输入未求值时保持未求值。旧比较类型的注册、显示和求值保留，已有图可继续使用。
- 核心 `anyValueType` 只用于静态数据输入，允许连接数值、字符串和布尔输出；执行信号不能接入，普通端口仍按原有具体类型校验。
- 恢复画布空白处左键拖动平移，同时保留中键平移、单击清除选择和 Esc 恢复。平移后拖回起点释放不会误触单击；左键在空白处开始新手势时结束待连线状态。

### 渲染性能与内存结论

GPU 对照使用 Qt 5.14.0、RTX 4060 Laptop GPU、原生 OpenGL、DPR=1，初始图为 11 个节点、6 条连线。每种尺寸各记录 600 个同步 GPU 离屏移动帧，计时包含事件处理、polish、sync、render 与 `glFinish`。

| 实际画布尺寸 | 原 Image 平均 / p99 | FBO + Cooperative 平均 / p99 |
| --- | --- | --- |
| 880×622 | 2.298 / 4.398 ms | 0.471 / 1.485 ms |
| 1520×972 | 5.263 / 10.098 ms | 0.534 / 1.145 ms |

这些数据说明本机连线层的同步离屏绘制成本下降，不能等同于实际窗口 FPS，也不能据此断言真实桌面全程无掉帧。连线仍会整体解析；另一个 411 节点、206 条连线的软件压力样例中，`resolveWires` 平均约 4.62 ms，本轮未增加连线缓存或局部重绘机制。

Qt 5.14 的 Canvas 默认开启抗锯齿，FBO 路径会申请 8 倍多重采样，实际采样数受硬件限制。按 RGBA8 颜色、深度/模板附件和 resolve 纹理估算，880×622、DPR=1 时图形资源约 35.5 MiB；该资源估算不能直接视为任务管理器的进程内存增量。

真实 threaded 渲染路径的一组独立启动进程对照，在 1280×730 窗口、880×622 画布、静置 2.5 秒后得到：

| 指标 | 原 Image | FBO + Cooperative | 差值 |
| --- | --- | --- | --- |
| 私有工作集 | 175.160 MiB | 176.609 MiB | +1.449 MiB |
| 私有提交大小 | 337.590 MiB | 380.070 MiB | +42.480 MiB |

为避免打断调试，这组窗口采用透明、不激活、输入穿透的设置，可能影响呈现和驱动分配。离屏三轮也观察到提交大小增加约 32～41 MiB，私有工作集没有相应增加。仅诊断时关闭抗锯齿，提交大小下降约 35 MiB；产品仍保留抗锯齿设置。

已确认此次渲染改动存在约 40 MiB 级别的提交成本。用户观察到的任务管理器「内存」列增加约 40 MB 尚未复现，仍需核对前后具体数值、构建配置及窗口尺寸；不能将该问题记为已定位或已解决。真实可见窗口呈现帧率和高 DPI 表现也尚未测量。

## 2026-11-12 框架重构与现有功能合并

以原工程已有功能为基线合并通用框架实现，保留节点库与成员拖放、分类折叠、已放置提示、六运算比较、画布快捷键、吸附与非法原因、手势取消和原连线绘制设置。调试关闭行为继续直接退出，打开另一张图时仍确认丢弃修改。

- 保留共享类型注册、参数与成员元数据、只读属性、启动快照、按端口求值和异步动作。运行实现和声明使用新的公开契约，不添加旧接口或旧图迁移层。
- 恢复仅用于数据输入的 `anyValueType`。通用比较使用两个独立输入，按现有数值、字符串和布尔比较规则求值；原大于、小于、等于类型仍可使用。
- 已连接输入可拉出原输出的连线，改接另一输入；只修改所拖连线，保留 ID 及其它分支，失败或取消保持原图，成功一次撤销。先单击再拖动同一输入也保持可用。
- 吸附预检和提交共同使用 `connectionProposal` 解析端点及替换连线 ID。这是新增的共享辅助函数，两个实际调用点需要相同的占用规则。
- Core 保留实际构建目标 `BlueprintFramework`，同时提供 `BlueprintCore` 和 `Blueprint::Core`；支持独立 Core 构建与安装包消费。

合并后的联合验证：Qt 5.14，Release，offscreen/software。七个仓库内测试目标与两个实际 Demo UI 验证目标全部通过（共九个目标）。比较测试 356 通过，包含 348 条矩阵数据；交互测试 8 通过，实际 Demo UI 测试 7 通过，以上数字均包含各自初始化和清理，未合计为业务案例数。验证包含只读禁用、真实鼠标拖放、比较选择、重连、取消、吸附、文本焦点、保存读取及撤销重做。Core-only 原构建目标、命令行示例、安装和 `find_package` 消费也通过。

原工程 Visual Studio 2019 / RelWithDebInfo 的 `BlueprintFramework-demo` 目标已重新构建通过；原路径 exe 完成 offscreen/software 启动检查，没有 QML 加载错误。同步前保存原文件备份并核对内容哈希，合并未覆盖其它模块文件。
