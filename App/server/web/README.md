# 网页节目播控

该目录包含一个基于 `cpp-httplib` 的本地 HTTP 服务和无外部依赖的响应式网页。服务复用现有 `TimelineRuntime`，所有运行时读取和播控操作都会切回 Qt 主线程执行。

## 功能

- 查看当前方案、播控状态、主时钟和节目进度
- 查看节目库、触发规则状态、指令数量、执行状态和节目时长
- 查看当前选中节目的指令时间、目标设备、执行参数、状态和错误信息
- 选择设备范围并与桌面共用 `filterDeviceIds`、`filterGroupNames`、`filterDeviceTypes`；网页显示类型分组条件，点选设备时保留已有分组条件，重置时清空三者
- 独立控制范围外指令的灰显/隐藏与播放执行；开启执行过滤后，播放期间锁定范围，显示方式仍可调整
- 显示桌面端编排的队列，支持移除、排序和清空队列；已入队节目显示角标
- 单节目与队列分别开始、暂停、继续和停止，队列为空时隐藏队列面板
- 停止时拖动进度条选择当前节目的起播时间，之前的指令跳过；播放队列从第一项的 0 开始
- 顶部显示所有运行中的时间线，区分主节目与触发节目，分别展示进度、剩余时间及暂停状态；切换所选节目仅改变指令查看对象
- 播放队列及顺序随桌面方案保存，重新载入后保持停止；旧方案载入为空队列
- 手动触发未运行的节目，不受整体播放状态限制
- 运行中的节目显示“停止”按钮，仅停止该时间线后续指令下发并回到停止状态，不发送设备停止指令；整体暂停时也可操作
- 运行中的节目在操作区左侧显示“同步船上音频”，沿用操作密码确认，将船上音频同步到该时间线的当前播放位置；整体暂停时禁用
- 查看设备类型与设备上报状态
- 可选 Bearer 访问令牌；默认仅建议监听本机地址

## 使用

模块已接入应用入口和构建目标。启动桌面程序后访问：

`http://127.0.0.1:8080`

服务默认仅允许本机访问，并随桌面程序退出而停止。

局域网访问时可在 `App/main.cpp` 中改为监听 `0.0.0.0`，并建议在启动前设置访问令牌：

```cpp
webControlServer.setAccessToken(QStringLiteral("请替换为随机令牌"));
webControlServer.start(QStringLiteral("0.0.0.0"), 8080);
```

## HTTP API

- `GET /api/v1/status`：完整播控快照
- `POST /api/v1/queue`：请求体为 `{ "timelineIds": ["..."] }`
- `POST /api/v1/device-filter`：支持可选字段 `deviceIds`、`groupNames`（字符串数组）、`executionFilterEnabled`、`showFilteredOut`（布尔值）；仅修改传入的字段。空设备和组条件表示全部设备，非空条件按并集匹配。播放期间不能修改执行开关，开启执行过滤时也不能修改设备或组条件
- `POST /api/v1/control`：支持下表中的 `action`

| action | 参数及行为 |
| --- | --- |
| `select` | `timelineId`：改变所选节目，不改变队列和正在播放的节目 |
| `start-current` | 可选 `timelineId` 和 `startTimeMs`（毫秒，默认 0）；播放当前节目，不修改队列 |
| `start-queue` | 始终播放已编排的队列，从第一项的 0 开始 |
| `pause` / `resume` / `stop` | 可选 `source` 为 `current` 或 `queue`；来源不匹配时拒绝操作，省略时控制全局播放 |
| `trigger` | `timelineId`：手动触发未运行的节目，不受整体播放状态限制 |
| `stop-timeline` | `timelineId`：停止指定运行中（含整体暂停时）的时间线调度；其他运行中的时间线继续。停止队列当前项会结束本轮队列推进并保留队列列表，不发送设备停止指令 |
| `sync-ship-audio` | `timelineId`：将船上音频同步到指定时间线的当前播放位置，仅在时间线与整体播放均处于运行状态时接受 |
| `start` | 兼容原有队列启动接口；可传 `timelineIds` 和 `startTimeMs`，不传队列时使用已编排队列 |

启动仅允许停止或完成状态，编排队列仅允许停止状态。快照中的 `currentTimelineId` 表示所选节目，`playbackTimelineId` 表示实际主节目，`queuePlayback` 表示当前会话是否来自队列。队列播完但触发节目仍在运行时，主节目为空、`queuePlayback` 保持 `true`。

方案格式升级为版本 6，时间线管理器格式为版本 3。继续兼容之前支持的方案版本 2、3、5 和管理器版本 1、2；旧版程序不能读取新格式方案。

启用令牌后，请求需带 `Authorization: Bearer <token>` 或 `X-Control-Token: <token>`。

## v2 语音设备控制接口

v2 用于先查找设备、按需读取详情，再触发预配置指令。原有四个 v1 播控接口及其响应保持不变；本轮新增的设备查询由 `/api/v1/devices` 迁移至 `/api/v2/devices`，旧的设备查询地址不再注册。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v2/devices` | 按名称和分组查找设备，每台仅返回 `name`、`type` |
| POST | `/api/v2/devices/info` | 精确查询一个或多个设备的详细信息 |
| POST | `/api/v2/commands/trigger` | 对指定设备批量触发同名的预配置指令 |

接口沿用现有 Bearer / `X-Control-Token` 鉴权，JSON 响应为 UTF-8，带 `Cache-Control: no-store`。POST 请求发送 `Content-Type: application/json`，请求体上限为 64 KiB。设备读写均在运行时所属线程执行。

### 1. 查找设备：GET /api/v2/devices

| 可选查询参数 | 匹配规则 |
| --- | --- |
| `name` | 名称包含该文本，忽略大小写 |
| `groupName` | 所属组中包含该完整组名，区分大小写 |

查询参数去除首尾空白后使用，省略或空字符串表示不限制该条件。两个条件同时非空时必须同时满足；都为空时返回全部设备；无匹配项时返回 HTTP 200 和空 `devices` 数组。不修改桌面或网页的全局设备筛选设置。

```text
GET http://127.0.0.1:8080/api/v2/devices
GET http://127.0.0.1:8080/api/v2/devices?name=音响
GET http://127.0.0.1:8080/api/v2/devices?groupName=游客船
GET http://127.0.0.1:8080/api/v2/devices?name=一号&groupName=游客船
```

外部调用时替换主机 IP，中文及特殊字符由客户端进行 URL 编码。成功响应每台设备只包含两个字段：

```json
{
  "ok": true,
  "devices": [
    {"name": "一号音响", "type": "音响"},
    {"name": "二号音响", "type": "音响"}
  ]
}
```

### 2. 精确查询详情：POST /api/v2/devices/info

请求仅包含 `devices` 字段，单个设备也使用数组。数组中每项仅采用以下一种标识，可以在同一批中混合使用：

- `{ "id": "device-..." }`：完整设备 ID。
- `{ "name": "一号音响", "type": "音响" }`：完整名称和设备类型。

标识按完整字符串匹配，区分大小写，不进行模糊匹配或首尾空白修正；字符串不能为空或全为空白。同一项不能混用 ID 与名称、类型，也不能包含其他字段。

```json
{
  "devices": [
    {"name": "一号音响", "type": "音响"},
    {"id": "device-请替换为二号音响的完整ID"}
  ]
}
```

每一项必须唯一匹配。空数组、非法标识、未知设备、歧义匹配或重复目标均返回错误，不返回部分详情。通过 ID 和名称加类型重复选中同一设备，也算重复。

成功返回 HTTP 200，结果按请求顺序排列，每台设备只包含以下六个字段：

```json
{
  "ok": true,
  "devices": [
    {
      "name": "一号音响",
      "type": "音响",
      "commands": ["开机", "关机", "播放音频"],
      "groupNames": ["游客船", "一区"],
      "id": "device-实际完整ID",
      "online": false
    }
  ]
}
```

`commands` 为设备已配置的指令名称列表，`groupNames` 为所属全部组名；无指令或未分组时分别为空数组。`online` 是最近的上报或探测状态，不保证代表查询时的即时状态。

### 3. 批量触发：POST /api/v2/commands/trigger

请求仅包含 `devices` 和非空字符串 `commandName`。设备标识和批量校验规则与详情查询一致；指令名称按完整名称查找，首尾空白会去除，区分大小写。

```json
{
  "devices": [
    {"name": "一号音响", "type": "音响"},
    {"id": "device-请替换为二号音响的完整ID"}
  ],
  "commandName": "开机"
}
```

先验证全部设备和指令，包括指令创建配置与保存的执行参数。任一设备不能唯一匹配、不支持该指令或配置无效，整批不下发；否则每台设备下发一次它自己配置的同名指令，使用各自保存的参数。同名指令在不同设备上的具体载荷可不同。

成功返回 HTTP 202：

```json
{"ok": true, "accepted": 2}
```

- `accepted` 是受理设备数量；202 仅表示已提交现有执行器，不代表设备实际动作成功。语音反馈应使用“已提交控制指令”，不能据此声称设备已完成操作。
- 本版不提供执行结果查询、自动重试或请求去重；客户端重复提交会再次触发。网络超时后不能假定未执行。
- 本版不接收动态 `params`；额外字段会返回 400，避免参数被静默忽略。需要执行参数的指令必须事先保存有效值。
- 不以 `online == false` 拒绝触发，以支持开机等动作；实际传输失败由现有执行器处理。
- 指令触发不改变播放队列、节目选择、时间线指令状态或全局设备筛选，也不受播放执行过滤范围限制；播放或暂停期间均可调用。它直接控制设备，可能与正在播放的时间线指令作用于同一设备。
- 整批校验只保证校验失败时不下发；提交后各设备独立执行，无法保证全部执行成功或回滚。原指令配置中的冗余发送策略仍然生效。

### v2 错误响应

错误沿用 `{ "ok": false, "error": { "code": "...", "message": "..." } }` 结构。批量校验遇到第一个错误即返回，设备索引在错误文字中从 1 开始。

| HTTP 状态 | error.code | 含义 |
| --- | --- | --- |
| 400 | `invalid_json` | POST 请求体不是有效 JSON 对象 |
| 400 | `invalid_request` | 请求缺少必填字段、指令名称无效或含额外字段 |
| 400 | `invalid_devices` | `devices` 不是非空数组 |
| 400 | `invalid_device_identifier` | 单项标识不符合 ID 或名称加类型的格式 |
| 400 | `duplicate_devices` | 多项标识选中了同一设备 |
| 401 | `unauthorized` | 已配置令牌但未提供有效令牌 |
| 404 | `device_not_found` | 某项标识找不到设备 |
| 409 | `ambiguous_device` | 某项标识匹配到多个设备 |
| 422 | `command_rejected` | 某台设备不支持指令，或指令配置、保存参数无效 |
| 503 | `runtime_unavailable` | 播控运行时不可用 |
