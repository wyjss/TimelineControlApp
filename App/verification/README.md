# 页面回归检查

复用 UICore 的 QuickTest runner，页面直接加载当前源码，不需要启动设备后端：

```powershell
cmake -S UICore_new -B build/uicore-ui-review -DCMAKE_PREFIX_PATH=C:/Qt/5.15.2/msvc2019_64
cmake --build build/uicore-ui-review --config Release
$env:PATH = 'C:/Qt/5.15.2/msvc2019_64/bin;' + $env:PATH
$env:QT_QPA_PLATFORM = 'offscreen'
$env:QT_QUICK_BACKEND = 'software'
$env:QT_QPA_FONTDIR = 'C:/Windows/Fonts'
& build/uicore-ui-review/verification/Release/UICoreQmlTests.exe -import App/verification/imports -input App/verification -o build/ui-pages-tests.txt,txt
ctest --test-dir build/uicore-ui-review -C Release --output-on-failure
```

Qt 路径按本机安装位置调整。测试覆盖名称与地址搜索、在线筛选、无结果时的选中状态、紧凑模式、分类切换，以及 1180 / 1700 宽度下编辑区的边界和返回概览。另覆盖 296 / 740 宽度下的指令名称显示、毫秒时间格式，以及 680 宽度下触发规则展开、收起和操作入口的边界。680 / 1100 宽度下检查点击规则文字、空白和启停开关均不打开编辑窗口，只有菜单中的“编辑”打开对应规则。密集事件检查覆盖标签分层、点击区域不重叠、溢出合并，以及移除重叠事件后恢复紧凑行高。指令集检查覆盖最窄编辑区右侧面板的默认 6 条指令、有无参数均先打开弹窗、别名默认值与自定义输入、取消不添加、添加时间和目标设备、播放期间禁用，切换至无指令设备、点击设备轨道保留当前面板、点击已有指令切换至时间轴指令面板，以及长列表选中定位。1180 / 1700 宽度下使用真实鼠标点击指令分段切换器的中央和边缘，检查双向切换、指令列表显示、条目选择及左右方向键切换。编辑状态下左右空间由轨道与指令面板使用，返回概览后恢复时间轴列表。测试不执行设备指令，也不写入方案。

该 runner 未注册 App 的 `deviceicon` 图片提供器，因此设备用例会出现 `Invalid image provider` 提示；图标需要在完整应用中检查。完整应用在首次显示前定位最左侧屏幕。

播放队列检查见 `tst_PlayQueue.qml`：覆盖 1180 / 1700 宽度下左栏底部固定、三行滚动、折叠、空队列隐藏与空间恢复、显式加入、编辑态入口及弹窗边界；检查队列从零开始且不改变节目选择，以及暂停、继续、完成后重播、停止保留队列、运行时禁止编排、排序、移除和清空。另检查单节目播放、暂停和完成时队列保持待播放，空队列隐藏，队列控件不能暂停或停止单节目，切换所选节目不改变正在播放的主节目。使用模拟管理器，不执行设备指令。

2026-09-06：Qt 5.15.2 / MSVC 2019 Release 下页面测试 15 项（含初始化与清理）通过，UICore 的 3 项 CTest 通过。相同环境的 UICore Standalone 在修改前后均有 28 条既有绑定循环，0 条递归布局、0 条 QML 加载或类型错误；不将该启动检查记录为通过。

网页播控回归执行 `node App/verification/tst_WebPlayback.cjs`，无需启动 HTTP 服务或设备后端。覆盖所选节目与实际主节目分离、单播与队列控制、完成后重播、请求来源、空队列隐藏，以及操作后的旧轮询响应不会覆盖新状态。

加载视频编辑器已接入 `TimelineManager`、`DeviceModel` 和 `TimelineCommandModel`，只展示 PC 设备的 `openVideo` 指令。编辑完成后自动写回当前时间线指令：拖动与缩放在松开鼠标时提交，数值输入在回车或失焦时提交，视频选择、播放选项和矩形操作按钮立即提交。页面不再保留草稿或提供“保存修改”按钮，方案文件仍通过全局保存写入。原始视频选项值和其他执行参数保留，不修改共享设备指令。回归时需检查编辑后的模型值、指令重排与选择、切换页面或时间线后保留修改、方案重载、新增删除、空状态，以及运行与暂停时禁改。

指令菜单的“克隆到…”使用独立组件 `VideoCommandCloneDialog.qml`，在当前时间线内选择原设备或其他配置了加载视频指令的 PC。目标视频按完整选项值匹配，缺失时必须重新选择；复制源指令的执行参数与默认值，绑定目标设备自己的加载视频指令。矩形超出目标画布时提示并保留原值，确认后选中新指令并展开、定位目标列表。回归检查输入失焦后打开菜单、跨设备与同设备克隆、原始 `$` 值与对象选项、缺失与空选项、时间校验、取消、新旧参数独立、旧版矩形、折叠与长列表定位、运行期间和时间线切换时禁用，以及方案保存重载。

时间线设备指令统一按 `startTimeMs` 触发，节目总时长取最后一条指令的触发时刻。拖拽和网页用例不再提供指令级 `durationMs`；旧方案执行参数中的同名字段不参与时长计算。需要固定节目长度的测试应在结束时刻添加事件，不再用虚构的指令持续时间延长节目。

时间轴指令在停止或暂停时允许添加、编辑、删除与 Ctrl 拖动，暂停编辑不改变播放位置；恢复后按新时间顺序执行待执行指令，早于暂停位置的指令跳过。已有指令的时间实际改变时，清除该指令的旧错误信息，按新时间重新判定：早于当前播放位置设为 `Skipped`，等于或晚于当前位置设为 `Idle` 并重新排队，已处理过的指令也可再次执行；未改时间的已处理指令保留原有结果，本轮不再触发。`tst_PageLayouts.qml` 覆盖暂停编辑、删除及弹窗打开后恢复运行时禁止提交，`tst_CommandDrag.qml` 覆盖暂停拖动后时间变更且播放位置不变。

暂停定位支持拖动刻度尺指针、双击刻度尺或输入时间；拖动时只预览，松手后提交并保持暂停，Esc、恢复运行、切换时间线或隐藏页面会取消未提交的定位。仅允许定位仍在执行的时间线，不移动全局主时钟及其他时间线，也不发送设备恢复指令。定位仅重置原位置与目标位置之间（包含两端）的指令：区间内早于目标时刻的标记跳过，目标时刻及之后的重新待执行；区间外保留状态、错误信息和已处理记录，同位置不重置，启动播放仍全量初始化。继续播放后才触发，跳到末尾也在继续后才完成并切换播放队列。`tst_CommandDrag.qml` 覆盖前后拖动、首尾边界、取消、数值输入、双击及停止时原有拖动行为。后端验收覆盖 20 秒前跳 35 秒跳过 30 秒指令、回退 10 秒重新执行、定位后增删改、并行时间线不变，以及旧 HTTP 回包不能覆盖重新执行的结果。

停止或暂停时拖动刻度尺指针，预览位置实际变化会触发当前 `Timeline::seekPreviewRequested(qint64 timeMs)`，参数为时间线内的毫秒位置；QML 直接调用该 C++ 信号，不增加转发函数。暂停时此通知不提交 seek、不重置指令状态；松手仍沿用原有提交路径。相同吸附时间不重复通知，取消拖动或松手本身不额外发送预览通知。运行时接收该信号，在暂停且时间线仍在执行时，通过 `PcVideoStateCalculator::stateAt()` 计算目标位置的视频进度，向未被播放过滤的 PC 发送 `seekVideo`；不发送加载、播放、暂停或关闭指令，不改变时间线执行状态。停止时仍仅更新本地预览。跳转作用于播放端已经加载的视频，不补齐跨越加载或关闭事件产生的差异。

时间线指令的单击仅选中并滚动视图，不移动当前游标或改变停止时的起播位置。指令列表每行悬停显示“定位”按钮：停止时移动预览及起播位置；暂停时仅对仍在执行的时间线提交定位，定位后保持暂停；播放中和完成时禁用。`tst_CommandDrag.qml`、`tst_PageLayouts.qml` 检查轨道与列表的单击不定位、显式定位及状态限制。

时间轴指令块与指令列表共用 `TimelineCommandContextMenu.qml`，右键先选中指令再打开菜单，取消菜单仍保留选中项，菜单中的“测试”直接使用被右键点击指令已保存的目标设备、设备指令和执行参数，停止、暂停、播放中及完成时均可测试。页面持有独立的临时测试指令并显示最近一次测试的状态或错误，测试不修改原指令的正式执行状态、游标及调度队列。菜单中的“定位”与列表定位按钮复用现有逻辑：停止时移动预览及起播位置，暂停时仅定位仍在执行的时间线并保持暂停，播放中、完成时及暂停的待执行或已完成时间线禁用。检查右键目标与当前选中项不同、取消菜单、Ctrl+右键、多个指令切换测试、异步成功和失败，以及原有左键选择和 Ctrl 拖动。
